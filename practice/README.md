# 实践手册：CRM + 交易系统

[总纲](../ROADMAP.md) · [进度](../PROGRESS.md)

## 项目定位与边界

练习场景是一家面向企业客户的商品销售公司：销售负责客户、商机和报价；交易模块负责订单、库存预留、模拟支付与退款；CRM 订阅成交事实更新客户统计和跟进任务。

先构建模块化单体，再由业务和测量结果决定演进。后续实践工程放在独立练习仓库，本仓库维护学习文档与脱敏证据；此版本没有创建业务代码。无需前端，使用 HTTP 请求、测试和数据库观测完成验收。

## 统一领域词汇

| 概念 | 本练习定义 | 数据归属 |
|---|---|---|
| 客户 Customer | 企业客户，有名称、唯一客户编码、负责人和启用状态 | CRM |
| 商机 Opportunity | 针对一个客户的一次销售机会，阶段 1 限定最多形成一个订单 | CRM |
| 报价 Quote | 商机下的版本化商品及价格方案；发布后明细不可变 | Sales |
| 订单 Order | 根据有效报价生成的商业快照，不随报价或客户名称变更重算 | Trading |
| 库存预留 Reservation | 为待支付订单占用商品可售数量，取消/过期释放 | Inventory，阶段 2 加入 |
| 支付 Payment | 模拟渠道产生的付款事实，有唯一渠道流水 | Payment，阶段 2 加入 |
| 退款 Refund | 对已确认支付的独立反向业务动作，不删除支付事实 | Payment |
| 成交统计 | 按订单正常确认支付累计毛成交额，按对应退款计算净成交额；异常收款单独对账 | CRM 可重建读模型 |

成交口径是练习约定，不等同于财务收入确认。每个新需求先说明涉及哪个事实、哪个模型和哪个不变量。

## 全阶段不变量

| 编号 | 必须保护的规则 | 首次验收阶段 |
|---|---|---|
| INV-01 | 金额用十进制精确表示，单币种 CNY；数量为正整数；订单明细及总额有快照 | 1 |
| INV-02 | 客户→商机→报价→订单的归属一致；订单不得引用其他客户的报价 | 1 |
| INV-03 | 已发布报价明细不可变；每个商机最多一个订单；重复转换不重复创建 | 1 |
| INV-04 | 未授权账号不能通过列表、详情、修改或导出取得他人客户数据 | 1；租户边界在 4 扩展 |
| INV-05 | 多表业务写入整体成功或整体失败；错误可定位但不暴露敏感详情 | 1 |
| INV-06 | 库存不为负；预留只确认或释放一次，数量守恒 | 2 |
| INV-07 | 同一支付/退款事实最多记账一次；取消与晚到支付按规则收敛 | 2 |
| INV-08 | 已提交的成交/退款事实最终可传递；重复/乱序/重放不重复改变统计 | 3 |
| INV-09 | 缓存和搜索不成为订单、支付的事实来源；可从权威数据重建 | 3 |
| INV-10 | 发布、迁移、恢复过程有检查点，未验证结果不得标为已完成 | 1 起，3–5 深化 |

## 技术与实验约定

- Java 21、MySQL 8.4/InnoDB、Spring Boot 稳定版、Maven；依赖版本按 [基线规则](../resources/REFERENCES.md#baseline) 锁定。数据访问先做最小 JDBC 对照，再用 MyBatis；数据库迁移默认 Flyway。
- 模块化单体从按业务分包开始，不要求每个包都拆成独立 Maven 模块。模块依赖通过测试验证；Spring Modulith 是可用辅助工具。
- 缓存用 Redis，MQ 用 RabbitMQ；Outbox 首先用轮询投递理解机制，不要求 Kafka/CDC。搜索先做一个最小模型，真实 Elasticsearch 作为加深练习。
- 日志和请求标识从阶段 1 建立；阶段 3 加入指标、追踪和告警。付费云服务不是前置。
- 使用虚构客户及商品。阶段 1 固定练习账号，阶段 2 模拟支付；不得把练习接口直接对外暴露成支付服务。
- 正常、边界和失败场景都要保留结果；实验清理只影响练习环境，不在共享或生产环境注入故障。
