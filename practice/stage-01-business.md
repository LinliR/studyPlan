# 阶段 1：客户 → 商机 → 报价 → 订单

[实践首页](README.md) · [上一阶段](stage-00-diagnosis.md) · [下一阶段](stage-02-correctness.md)

## 目标、前置与范围

入口：已完成诊断并选择弱项。完成一个有权限、数据约束、事务、测试和启动说明的模块化单体。此阶段不加入库存、真实支付、消息队列、微服务或多租户；这些通过后续需求演进加入。

主学 M01、M05、M06、M07；同步使用 M11-1/2 的业务建模、M12-1 的对象级权限、M10-1 的环境与日志。任务 ID 用于进度和证据引用。

## 固定业务规则

### 客户与商机

- 固定三个练习账号：销售 A、销售 B、管理员。账号由练习环境配置；密码不写入仓库。最小认证使用 Spring Security HTTP Basic，只在本机练习使用；状态改变请求使用框架 CSRF 防护与测试支持，不以关闭安全检查让用例通过。手工客户端先读取 CSRF token，保留同一会话 cookie，再携带认证和指定 token 请求头执行写操作。
- 销售只能创建属于自己的客户，并访问当前由自己负责的客户及其商机、报价、订单。管理员可查看全部并转移负责人。负责人来自可信身份；销售传入其他 ownerId 应被拒绝。
- 客户编码唯一，名称非空，客户可停用。停用后历史可查询，不能新建商机、发布报价或转订单；草稿可保留。
- 商机属于一个客户，状态为 OPEN/WON/LOST。仅 OPEN 可创建或发布报价、首次转订单；转订单成功后变为 WON。关闭为 LOST 后不得转单。阶段 1 暂不做重新打开与硬删除。

### 金额与报价

- 币种仅 CNY，单价非负且最多两位小数；不隐式舍入超精度输入。数量为正整数；使用 BigDecimal，金额存 DECIMAL(15,2)，应用同时拒绝总额溢出。金额 0.00 允许。
- 行金额=单价×数量，总额=行金额之和。第一阶段不加税、折扣或运费；需要学习舍入时做独立实验，不擅自改变业务规则。
- 报价以 `(opportunityId, version)` 唯一。版本递增，在并发创建时通过锁定商机行分配版本；允许历史版本并存，最多一个 ISSUED 版本。
- 状态为 DRAFT → ISSUED → CONVERTED；发布新版本时，原 ISSUED 版本在同一事务内改为 SUPERSEDED。DRAFT 可修改；发布后只允许状态变化，明细不可变。
- 发布时必须至少一行，客户启用、商机 OPEN，`validUntil > now`。只允许在 `now < validUntil` 时首次转换。用注入 Clock 测试时刻，保存 UTC Instant，展示时才转换时区。

### 订单与重复操作

- 订单保留客户名称、来源报价 ID/版本、SKU、商品名称、单价、数量、行金额和总额快照；不信任客户端上传的成交总额。
- 第一次转单在同一事务内校验业务、创建订单及明细、修改报价为 CONVERTED、商机为 WON。锁定商机行串行化该商机的发布与转单操作。
- 约束：每个商机最多一个订单，来源报价唯一。重复转换同一已转换报价，授权通过后返回原订单，HTTP 200；第一次创建为 201。该重试不重新判断报价是否过期或客户是否停用。
- 同一商机的其他报价不能再创建订单，返回 409。阶段 1 订单状态只有 CREATED，阶段 2 再演进支付/取消状态；不假装已经发生支付。

## 最小模型与模块边界

| 模块 | 模型/表 | 必须明确的约束 |
|---|---|---|
| 身份支持 | 练习账号/角色配置 | 身份可信、日志不泄漏密码；账号管理不是本阶段功能 |
| CRM | customer、opportunity | customer.code 唯一；归属引用有效；ownerId 不由普通销售任意指定 |
| Sales | quote、quote_line | 商机内版本唯一；明细序号唯一；数量/金额合法；引用有效 |
| Trading | orders、order_line | opportunity_id 唯一；source_quote_id 唯一；金额/历史快照完整 |

用数据库主键、唯一键、外键与 CHECK 保护可表达的规则；状态转换、权限和跨表金额一致性由应用事务保护并测试。不要声称单行 CHECK 能检查订单明细合计。

按业务分包，各模块仅暴露必要的应用接口；控制器只负责协议，应用服务编排事务，领域对象维护规则，仓储处理持久化。初始同库本地事务可跨模块编排；直接使用其他模块内部 Mapper 的访问应被依赖检查阻止。

## 最小接口契约

这些是练习实现规格，当前仓库尚未实现接口。ID 由服务端分配；成功响应至少包含 ID 和状态，金额用十进制字符串表达；列表默认 20 条、最多 100 条，并按稳定 ID 排序。

| 方法与路径 | 用途与关键输入 | 成功结果 |
|---|---|---|
| GET /csrf | 已认证练习客户端取得当前会话的 CSRF token | 200，token 与 headerName；客户端保留会话 cookie |
| POST /customers | code、name；销售归自己，管理员可指定合法 ownerId | 201，customerId |
| GET /customers；GET /customers/{id} | 当前权限范围的列表与详情 | 200 |
| PATCH /customers/{id} | 名称/启用状态；管理员另可转移负责人 | 200，修改后的摘要 |
| POST /opportunities | customerId、title | 201，opportunityId、OPEN |
| POST /opportunities/{id}/close | 关闭为 LOST | 200；已有订单则 409 |
| POST /opportunities/{id}/quotes | validUntil、明细（sku/name/unitPrice/quantity） | 201，quoteId、version、DRAFT |
| PUT /quotes/{id} | 修改草稿完整内容 | 200；非草稿 409 |
| POST /quotes/{id}/issue | 发布当前草稿 | 200，ISSUED；非法状态 409 |
| GET /quotes/{id} | 授权后的报价及明细 | 200 |
| POST /quotes/{id}/orders | 从服务端报价快照转单，无客户端价格 | 首次 201，重试 200，同一个 orderId |
| GET /orders/{id} | 订单快照 | 200 |

输入格式/数值非法 400，认证失败 401，已认证越权 403，不存在 404，状态/唯一性冲突 409，未预期系统错误 500。练习统一错误体含 `code`、`message`、`requestId`，不回传 SQL、凭据或堆栈；控制器异常与安全过滤器的认证/拒绝处理都要覆盖。CSRF 校验失败为 403，可能先于认证处理发生，因此认证缺失用安全的 GET 请求单独验收，其他业务写入测试携带合法 token。

## 验收场景与预期

固定测试时刻 `2026-01-01T00:00:00Z`，报价到期 `2026-01-02T00:00:00Z`；C001 属于 A，C002 属于 B。SKU-A 19.90×3，SKU-B 0.10×3，总额 60.00。

| 编号 | 场景 | 必须得到的结果 |
|---|---|---|
| T1-01 | A 为 C001 创建商机、报价、发布并转单 | 首次 201；订单 CREATED、报价 CONVERTED、商机 WON；金额 60.00 |
| T1-02 | 同一报价再次转单，包括报价已过期后重试 | 200，同一订单 ID；库中仍只有一个订单 |
| T1-03 | A 查看/修改 C002，或传入 B 的 ownerId 创建客户 | 403，客户内容不泄漏，无写入 |
| T1-04 | 未认证 GET；不存在的对象；非法金额或空明细发布；缺失/错误 CSRF 的写请求 | 分别 401、404、400、403；错误含 requestId |
| T1-05 | 当前时刻恰等于 validUntil | 首次转单 409；无订单或状态残留 |
| T1-06 | 发布新版本后用旧版本转单；修改已发布明细 | 均 409；旧版 SUPERSEDED，金额不变 |
| T1-07 | 客户停用或商机 LOST 后首次转单 | 409；历史读取仍按权限允许 |
| T1-08 | 订单主表写入后、明细写入前注入异常 | 500；订单/明细不存在，报价仍 ISSUED，商机仍 OPEN |
| T1-09 | 两个请求并发转换同一报价 | 一个 201、一个 200，返回同一订单；约束无重复 |
| T1-10 | 发布两份新报价与转单相竞争 | 商机锁决定串行结果；至多一个有效发布版本、一个订单；失效操作 409 |
| T1-11 | 修改客户名称，或修改原始明细列表 | 已有订单名称与金额快照不变 |
| T1-12 | 以全新数据库启动，再重复执行迁移流程 | 结构/版本正确；重复启动不重复建表或破坏数据 |
| T1-13 | 金额恰为 0、超过两位小数、总额超 DECIMAL 范围 | 0 合法；超精度与溢出 400，禁止静默截断 |
