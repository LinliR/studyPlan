# 阶段 4：架构决策与最小迁移

[实践首页](README.md) · [上一阶段](stage-03-resilience.md) · [下一阶段](stage-05-transfer.md)

## 目标与前置

入口：已有正确性、性能、可靠性证据。主学 M11/M12，联动 M09/M10。交付一份能评审、能验证、能回退的架构决策；使用 [ADR 模板](../templates/architecture-decision.md)。

## 统一决策题

CRM 报表与交易共享数据库和发布流程，查询增长开始影响下单尾延迟；团队希望 CRM 能独立演进，并要求未来支持租户隔离。

以下是教学假设而非已测事实：2 个开发小组，每组 3 人；峰值读 200 次/秒、写 20 次/秒；100 万客户、1,000 万订单；报表允许 60 秒延迟，库存与支付不允许由陈旧读模型判定。根据真实工作可替换，但必须记录变更后的参数与理由。

设计先计算数据增长、索引/备份/复制成本和连接/在途请求预算，再用练习机器可承受的数据规模验证机制，不能把缩小实验直接宣称满足全部目标。

## 任务与交付

| 任务 | 必须完成的工作 | 验收 |
|---|---|---|
| S4-01 业务边界 | 明确 CRM、Sales、Trading、Payment 的词汇、不变量、拥有的数据与跨边界流程 | 系统/模块图及调用、事件与权限边界清楚 |
| S4-02 方案比较 | 比较单体内优化、异步独立读模型、拆分 CRM 服务；估算开发、运行、运维、迁移成本 | 至少三个可行候选，决策与假设有证据，触发重评的阈值明确 |
| S4-03 容量与可靠性 | 推导平均/峰值、数据保留、扩容上限、可用性和恢复目标 | 单位与口径一致；敏感参数变为 2 倍时重新计算 |
| S4-04 租户隔离 | 增加两个练习租户，定义可信租户上下文，覆盖 DB/缓存/消息/搜索/导出 | 两租户同业务编号可共存；跨租户请求和事件被拒绝或隔离 |
| S4-05 最小迁移 | 默认将 CRM 成交读模型迁移到独立存储，保留已有模块接口；只有 ADR 支持时再拆部署 | 回填、追平、对账、切换、回退各有证据 |
| S4-06 设计评审 | 提交完整方案，演练旧消费者/迁移中断/服务不可用 | 回答失败行为、兼容与操作责任；记录评审导致的修改 |

## 默认迁移演练步骤

1. 保留交易支付/退款事实的唯一权威写入端，停止依赖跨模块直接 JOIN，先通过明确查询接口访问。
2. 建立新读模型与事件消费去重；先开始保留/消费增量事件，再导入历史事实，以稳定支付/退款标识幂等合并，避免快照与事件重叠重复计数。
3. 影子查询对比客户数、成交毛额、退款额和净额；记录消费位置/未处理年龄，以及历史回填检查点。
4. 先对少量练习客户切换读路径；阈值为同一事实截止点下金额完全一致、缺失/重复事实为零，且延迟达成事先记录的目标。未满足则停止切换。
5. 注入回填中断、重复/乱序增量和新读模型不可用，验证恢复与降级；错误时切回旧读路径，保留增量事实便于重试。
6. 演练中不删除旧数据源或旧接口。真正移除旧路径必须等观测和数据保留条件满足；在 ADR 写清退出条件。

如果测量不支持拆服务，就提交保留单体的决策及上述读模型迁移实验。练习目标是证明演进安全，不预设微服务更好。

## 安全与兼容场景

- 相同 customerCode 在不同租户创建；伪造 tenantId 不能切换身份。原数据迁入默认租户的步骤可回退并可核对。
- 缓存键、搜索过滤、数据库唯一约束与外键引用边界、事件消费上下文必须包含或校验租户归属。
- 旧消费者收到新增可选字段仍能处理；未知不兼容 schemaVersion 进入明确失败处理，不静默丢弃。
- 客户删除/停用与历史订单、审计、统计有明确保留政策；演练使用虚构数据。

## 阶段出口

- [ ] 交付业务目标、架构图、候选比较、容量/成本、安全、接口与事件契约、迁移/回滚、测量限制。
- [ ] 至少一次迁移中断恢复与一次切回旧路径成功。
- [ ] 多租户负例覆盖所有已实现的数据入口；不靠前端隐藏实现隔离。
- [ ] 变式复测：团队缩至 2 人或流量增加 10 倍，重新解释选择及改变决策的证据。
- [ ] 无外部评审者时标记模拟评审，真实协作验证留给阶段 5。
