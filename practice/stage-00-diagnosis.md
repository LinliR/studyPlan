## 目标与执行方式

这不是录取考试。目标是用四份可复核的结果定位弱项，并选择第一轮学习任务。

先独立作答；卡住时记录卡点，再查资料继续，不把查资料后的结果改写成一开始就会。暂时没有可运行环境时先给模型/SQL/时序和预期结果，执行证据标记“待补”，不能认定已达到 L2。第一轮不需要完整 Spring 服务。

准备 Java 21、编辑器及本地或容器 MySQL 8.4。环境不就绪先学 M07-4 与 M10-1；诊断代码可在独立练习目录中编写。每题用 [证据模板](../templates/evidence.md) 记录。

## D0-1 金额、快照和状态

**题目：** 客户 C001 的商机 OPP001 有一份报价：商品 A 单价 19.90、数量 3；商品 B 单价 0.10、数量 3，币种 CNY。定义客户、报价版本、报价明细、订单快照与异常；报价发布后不能修改明细，只有有效报价可转订单。

任务：

1. 写最小 Java 模型，计算总额；金额通过十进制字符串构造。
2. 定义草稿、已发布、已转换三个状态及合法转换；有效期采用可替换 Clock。
3. 修改创建报价前的原始明细列表，观察已发布报价是否变化。
4. 测试空明细、负单价、数量 0、到期时刻和重复转单。
5. 解释为何选择值对象、异常类型和快照范围，不要求先使用框架。

判定要点：总额为 60.00；非法输入被拒绝；历史快照不变；重复操作行为有定义；恰到有效期边界按失效处理。能输出正确数字但不能解释 scale、复制与状态约束，仍有基础待补。

映射：[M01-1/3/4](../modules/m01-java.md)、[M11-1](../modules/m11-architecture.md)。

## D0-2 建模、SQL 与执行计划

**题目：** 为客户、订单、订单明细设计关系表，字段至少含负责人、订单状态、创建时间和金额。查询“某负责人在指定时间段的客户成交额排行”，本题临时以 PAID 订单为统计来源，避免与阶段 1 未引入支付混淆。

测试数据：

| 客户 | 负责人 | 订单 |
|---|---|---|
| C001 | A | PAID 60.00，含两行明细；CANCELLED 100.00 |
| C002 | A | PAID 40.00，含一行明细 |
| C003 | A | 无订单 |
| C004 | B | PAID 200.00 |

任务：建表并说明主键/唯一键/外键/金额类型；写查询（要求保留无成交客户，显示 0）；采用半开时间区间 `[from, to)`；解释 LEFT JOIN 筛选位置；为负责人、时间与排序提出索引并查看执行计划。

判定要点：A 的结果是 C001=60.00、C002=40.00、C003=0.00；不得因连接明细重复累计订单总额，不得包含 B；时间恰为 to 的订单不计入。小数据执行计划不能证明大数据性能，需说明这一限制。

映射：[M05-1/2/3](../modules/m05-data.md)。

## D0-3 事务与并发故障

**题目：** 库存为 1，两个请求同时“查询余量大于 0，然后扣减”。

1. 在纸上画两个请求都读到 1 的交错时序，预测结果。
2. 用两个独立数据库连接及明确同步点复现错误写法；记录隔离级别与自动提交设置。
3. 用数据库条件更新 `available = available - 1` 且条件 `available > 0` 修复，依据受影响行数判断成功，不把示例当完整库存方案。
4. 在订单写入与扣减之间注入异常，检查是否全部回滚；说明本地 synchronized 能否保护两个服务实例。

判定要点：最多一个请求成功，库存最终为 0；失败事务不留下孤立订单；结果需有实际行数和时序证据。若仅能描述不能复现，记“能解释但不会做”。

映射：[M03-1/2](../modules/m03-concurrency.md)、[M05-4/5](../modules/m05-data.md)。

## D0-4 测试与错误定位

**题目：** 为“报价转订单”的最小应用服务补测试；已有安全练习项目可使用真实接口，否则先用纯 Java 服务与仓储接口，不依赖创建完整系统。

1. 验证正常创建、过期报价、其他负责人操作、仓储抛异常。
2. 记录请求标识、业务步骤和失败原因；日志不包含密码或完整客户联系方式。
3. 给出异常到 HTTP 状态的预期映射；尚无 HTTP 层则将集成验证标记“待补”。
4. 故意删除一个状态检查，观察是否有测试失败；解释哪个测试需要真实数据库才有价值。

判定要点：测试检验行为而非只验证方法被调用；异常原因可定位；能区分单元与集成测试的证明范围。模拟仓储成功不能证明真实事务回滚。

映射：[M06-4/6](../modules/m06-spring.md)、[M07-3](../modules/m07-engineering.md)、[M12-1](../modules/m12-security.md)。

## 诊断出口与第一轮任务

在进度表逐题填写三选一结论和帮助来源，不计算容易掩盖弱项的总分：

- 能独立完成：记录证据，阶段 1 可复用同类成果，仍须通过集成验收。
- 能解释但不会做：将对应实验选为下一主任务，读资料后立即复做。
- 尚未理解：先补单元前置，完成最小反例后再回题目。

优先顺序：金额/状态错误 → 数据约束/事务错误 → 权限错误 → 测试定位不足 → 性能与更深机制。一次只选择一个主单元，最多一个前置补充。

离开阶段 0 的条件是四题都有结果或具体阻塞记录、每个弱项映射到模块、第一轮任务与通过标准明确；不是要求诊断全部通过。进入阶段 1 后补齐被标记为待执行的环境与集成证据。
