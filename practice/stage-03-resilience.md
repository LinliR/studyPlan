# 阶段 3：让系统在故障下运行

[实践首页](README.md) · [上一阶段](stage-02-correctness.md) · [下一阶段](stage-04-architecture.md)

## 目标与前置

入口：阶段 2 正确性通过，能够观测单进程与数据库故障。主学 M08/M09/M10，权限与审计沿用 M12。新增 Redis、RabbitMQ、Outbox、CRM 成交读模型及跟进任务，验证 INV-08/09/10。

## 事件与数据约定

- 权威支付与退款事实属于交易/支付模块；CRM 统计与跟进任务可重建。订单创建不是成交事件，只有订单正常确认支付才发 OrderPaid，对这笔成交确认退款才发 OrderRefunded。取消后晚到等异常收款及其退回仍留在资金对账台账，不产生这两类成交事件，不计入 CRM 成交额或生成跟进任务。
- 业务更新与 outbox 插入同一数据库事务。事件包含 eventId、eventType、schemaVersion、aggregateId、aggregateVersion、customerId、金额/币种、发生时间、correlationId；退款含原支付标识。事件内容是必要业务快照，不含客户联系方式等多余信息。
- 轮询投递器确认 broker 接受后标记已发送；标记失败允许重复投递。消费者把事件去重登记、事实落表、统计更新和跟进任务写入同一本地事务，提交后再确认消息。
- 以支付/退款事实表为可重建依据，按 eventId 与业务流水双重约束防止同一事实被不同事件 ID 重复表达。退款先到时暂存，等待支付事实后重算；超出约定等待窗口进入对账，不盲目形成负净额。
- 一次 OrderPaid 生成一个跟进任务，不发送真实邮件/短信。重放不重复生成；OrderRefunded 调整净成交额，不删除历史支付事实。
- Redis 仅缓存客户摘要/读模型，业务写入以数据库为准。缓存中断时实行有界回源；搜索练习保持与 M08 相同的重建及权限规则。

## 任务与交付

| 任务 | 执行内容 | 验收 |
|---|---|---|
| S3-01 缓存 | 定义缓存键、TTL、允许陈旧窗口；注入热键和断连 | 不读缓存决定扣库存/支付；有界回源、恢复可重建 |
| S3-02 可靠事件 | 实现 outbox 轮询、确认、重试与处理状态查询 | 逐个故障窗口都能恢复；失败有原因、次数和下一处理入口 |
| S3-03 幂等读模型 | CRM 消费支付/退款事实，更新统计和跟进任务 | 重复、乱序、重放与重建结果一致 |
| S3-04 可观测性 | 日志、指标、追踪串起订单到 CRM；定义 SLI/SLO | 成功率、尾延迟、最老 outbox 年龄、队列积压与失败可观察 |
| S3-05 韧性与告警 | 定义总超时、有限重试、隔离、限流和降级 | 下游失败不拖垮无关请求；告警含处理指引 |
| S3-06 恢复与复盘 | 在隔离环境演练故障、备份恢复和发布回退 | 恢复校验通过，实际 RTO/RPO 与目标有对照；完成复盘 |

## 必测故障窗口

| 注入时点或故障 | 预期业务行为与恢复证据 |
|---|---|
| 业务提交前退出 | 业务和 outbox 都回滚，无假成交 |
| 提交后、发布前退出 | outbox 仍可查询，重启后投递 |
| broker 确认后、标记发送前退出 | 可能重复投递；CRM 业务效果不重复 |
| 消费者写入前退出 | 未提交，消息重新处理 |
| 消费者提交后、ack 前退出 | 重投但统计和任务不重复 |
| 退款先于支付到达 | 记录等待关联事实；最终净额正确，超时触发对账 |
| 永久坏消息 | 有限重试后进入隔离/死信处理，不堵死正常消息；人工修复后可重放 |
| Redis 不可用，数据库容量有限 | 缓存回源受限，部分非关键查询可拒绝/降级；交易正确性不受损 |
| 数据库从备份恢复到较早时点 | 检查 outbox、去重表与业务事实的一致性，解释可能丢失窗口并对账 |

教学验收在依赖恢复后设定一个可测量目标：固定 1,000 条事件应在 60 秒内处理完且金额/任务数正确。它是本地练习目标；不足时先报告瓶颈与实测，不伪称达标，也不等同生产 SLO。

## 阶段出口

- [ ] 每个故障场景都有注入步骤、预期/实际、恢复证据与残余风险。
- [ ] 从权威支付/退款事实重建 CRM 统计，结果与增量处理一致。
- [ ] 完成一次告警触发与处置、一次独立实例恢复、一次失败发布回退。
- [ ] 使用 [故障复盘模板](../templates/incident-review.md) 写用户影响、时间线和可验证改进。
- [ ] 变式复测：将成交事件改为客户归属变更，重新讨论权限缓存、顺序和历史数据访问。
