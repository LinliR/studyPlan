## 学习问题与前置

为什么同样能运行的业务代码，在金额、集合、异常和时间边界上会得出不同结果？进入时应能独立编写类、方法和简单测试；不足处先补基本语法。目标：L3，能定位违反对象契约和资源管理规则的错误。

## 最小实验与项目映射

**实验 A：报价快照。** 先写金额与报价模型，再把外部可变明细列表传入报价；修改原列表，检查报价是否被污染。用防御性拷贝修复，说明复制列表与复制元素的差别。业务规则使用阶段 1 的单币种、两位小数基线。

**实验 B：集合契约。** 把一个参与 hashCode 的字段可变的客户对象放入 HashMap；修改字段后查找，再改成稳定标识作键。提交原始输出、修复版本及解释，不以遍历恰好找到元素代替契约分析。

| 场景 | 验证 |
|---|---|
| 正常 | 两条报价明细求和，输出金额和版本快照 |
| 边界 | 空明细、0.10、0.00、跨时区到期时间、同值不同 scale 的金额 |
| 失败 | 负单价、负数量、非法状态修改、资源读取中途异常 |

项目落点：客户标识、报价 Money、报价版本、订单快照、CSV 导入错误报告。

## 自测与模块验收

1. BigDecimal 的 equals 与 compareTo 有什么不同？你的金额值对象采用什么相等语义？通过：能说明 scale，并保证 equals/hashCode 一致。
2. 为什么给字段加 final 仍可能被外部修改？通过：用可变列表或元素展示反例并修复。
3. List<Integer> 为什么不是 List<Number>？通过：指出如果允许赋值会怎样破坏类型安全，并用通配符表达读写边界。
4. 代理能拦截哪些调用？通过：画出经过代理与目标内部直接调用两条路径，不把一种代理实现的限制推及所有机制。

通过单元验收后，再把报价模型换为“合同版本”闭卷实现；能诊断注入的金额/可变性错误才达到 L3。

## 一手资料与阅读顺序

主入口：[Java 官方教程](../resources/REFERENCES.md#java)。依次读语言与对象、泛型、Collections/Streams、异常与反射；每次只读对应单元。

核对依据：[Java 21 API 与 JLS](../resources/REFERENCES.md#java-spec)，重点查 BigDecimal、Object、Map、AutoCloseable、java.time 与 JLS 类型/泛型章节。源码使用本机匹配补丁版本的 src.zip，记录具体版本。

## 选修与边界

JPMS、MethodHandle 深入、注解处理器、JNI、Foreign Function & Memory 和框架级元编程按工作需求选学；预览特性不进入 Java 21 基线作业。
