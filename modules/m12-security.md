## 最小实验与项目映射

**实验 A：对象级越权。** 账号 A 与 B 各有客户；A 获得 B 的客户 ID 后尝试详情、修改、列表条件、报价转订单和导出。阶段 1 规则默认返回 403；接口不得泄漏对象内容。客户不存在返回 404，此存在性策略只用于练习，后续安全评审可重新决定。

**实验 B：隔离贯穿。** 阶段 4 加租户后，分别尝试伪造 tenantId、缓存命中另一租户、搜索跨租户、重放错误租户事件。测试必须走真实授权边界，不能只检查前端按钮隐藏。

**实验 C：评审表达。** 为“主管能否跨部门导出客户”列出业务价值、权限风险、数据最小化和审计方案。记录评审问题、修改以及仍未解决的事项。

| 场景 | 验证 |
|---|---|
| 正常 | 负责人访问自己的客户，管理员操作留下审计 |
| 边界 | 客户转移、角色撤销、令牌过期、缓存尚未失效 |
| 失败 | 跨客户/跨租户访问、恶意参数、失效密钥、带敏感数据的错误日志 |

## 自测与模块验收

1. 在请求里加 tenantId 为什么不等于隔离？通过：解释可信身份与服务端绑定，并检查所有数据路径。
2. 防 SQL 注入为何不能保护任意 URL 回调？通过：区分数据库输入与网络出站信任边界。
3. 审计与普通调试日志有什么区别？通过：说明用途、字段、保留与访问约束。
4. 如何让同事评审你的方案，而不只是听结论？通过：给出约束、候选方案、证据与待决问题。

至少提交权限矩阵与负例结果、客户数据流威胁模型、一次方案评审记录。练习不用真实客户资料或真实支付凭据；模拟评审如实标记。

## 一手资料与阅读顺序

主入口：[OWASP 与 Spring Security](../resources/REFERENCES.md#security)，先读授权/输入处理/日志，再读对应框架的防护机制；TLS 和 HTTP 回查 M02 资料。根据项目入口选择安全控制，避免无依据地堆清单。

## 选修与边界

OAuth2/OIDC 协议深入、策略引擎、复杂组织权限、专业渗透测试为选修。阶段 1 用最小认证方案完成边界验证，之后再演进身份体系。
