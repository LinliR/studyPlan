## 学习问题与前置

一条请求如何经过安全过滤、参数转换、应用逻辑、事务和数据库？注解为什么有时不生效？前置：M01 异常/反射/代理，M05 JDBC 与事务基础，HTTP 不足先补 M02-5。目标 L3。

## 最小实验与项目映射

**实验 A：请求的路径。** 为报价转订单画时序图：安全过滤→控制器→应用服务→仓储→数据库→响应。跟踪成功与异常两个分支，记录事务开始/结束和异常转换的位置。

**实验 B：事务失效。** 在隔离实验中构造代理外部调用和同对象内部调用；分别在第二次写入前抛异常。查询真实数据库验证结果，再把事务边界移至清晰的应用服务入口。不要只看到注解就判定事务存在。

**实验 C：配置解释。** 让练习环境读取两个冲突配置，依据对应版本官方规则预测最终值，再查实际配置与条件报告；移除冲突并说明配置归属。

| 场景 | 验证 |
|---|---|
| 正常 | 合法账号完成报价转订单，返回创建资源标识 |
| 边界 | 空明细、重复请求、未知客户、过期报价 |
| 失败 | 未认证、跨负责人访问、数据库写入失败、错误装配、代理未经过 |

## 自测与模块验收

1. 为什么控制器里调用另一个方法不一定开启新事务？通过：画调用对象与代理路径，注明代理机制。
2. 单元测试通过为什么接口仍可能提交部分数据？通过：说明 mock 和测试事务可能遮蔽的边界，补集成测试。
3. CORS 与权限校验解决的是同一个问题吗？通过：分别解释浏览器来源限制、身份和数据权限。
4. 新增依赖为何改变了应用行为？通过：用自动配置条件定位原因，不靠猜测移除依赖。

模块证据包括请求时序、事务故障与修复、配置定位、权限与错误响应测试。源码只追当前请求链上的关键节点。

## 一手资料与阅读顺序

主入口：[Spring Framework 与 Boot](../resources/REFERENCES.md#spring)：Core/IoC → AOP/事务 → Web MVC → Boot 配置与测试。安全查 [Spring Security](../resources/REFERENCES.md#security)。资料必须与实际依赖主版本匹配，避免把 Boot 3/4 的配置直接混用。

## 选修与边界

手写最小 IoC 可选；完整 Spring 仿制不是毕业要求。WebFlux、响应式数据访问、gRPC、GraphQL、自定义 starter 按具体问题选学，先掌握同步 MVC 链路。
