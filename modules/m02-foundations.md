# M02 计算机基础与算法

[总纲](../ROADMAP.md) · [学习方法](../METHOD.md)

## 学习问题与前置

一次请求为什么会慢？一个循环、一个系统调用和一次网络往返分别消耗什么？前置：M01 基本类型、集合与 IO。目标：结构与算法 L2，请求链路和资源定位逐步达到 L3；按当前问题补课，不先背完整 OS 教材。

## 最小实验与项目映射

**实验 A：客户去重。** 固定同一批虚构客户，先做双重循环，再使用散列表。以 10³、10⁴、10⁵ 条输入比较操作规模与耗时；不要只凭一次计时推导复杂度。测试全重复、全不同和空输入。

**实验 B：请求的一生。** 为练习服务分别构造：地址解析失败、端口未监听、下游延迟、接口返回 500。记录客户端错误、服务器是否收到请求、各阶段耗时，解释应在哪一层排查。

**实验 C：组织关系。** 把 CRM 部门层级建成树；加入一条形成环的错误关系，用图算法拒绝它。提交正常树、单节点、深链与环四组测试。

项目落点：客户去重、组织树权限范围、Top K 成交客户、外部接口超时排查。

## 自测与模块验收

1. 应用延迟高而 CPU 低说明什么？通过：提出至少两个假设，并列出区分它们的观测手段。
2. 为什么收到 TCP 确认不等于业务已成功？通过：区分传输、应用处理与持久化边界。
3. 对 100 万客户取前 100 名，排序和堆有什么差别？通过：比较复杂度，并讨论输入更新频率。
4. 一次文件读取是否一定访问磁盘？通过：画出用户缓冲、页缓存和设备的关系。

每轮算法至少完成一个未照抄的解法、边界测试和复杂度解释。阶段出口换一个业务对象复测，不用题量代替掌握。

## 一手资料与阅读顺序

主入口：[OSTEP](../resources/REFERENCES.md#foundations)，按线程/调度、内存、IO/文件章节定点阅读；[MIT 算法课程与 HTTP 标准](../resources/REFERENCES.md#foundations) 分别对应算法和协议。

Linux 实验与开发机 macOS 的命令、调度和 IO 实现分别记录；epoll 是 Linux 机制，不把开发机观察直接作为 Linux 结论。

## 选修与边界

汇编优化、编译器实现、内核开发、竞赛算法、网络驱动为选修。AIO、零拷贝与 Netty 深入放在能解释基础 IO 路径之后。
