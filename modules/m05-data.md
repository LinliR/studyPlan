## 学习问题与前置

数据什么时候算正确，SQL 为什么这样执行，提交后的结果如何恢复？前置：M01 对象、集合、异常；存储机制补 M02-4。目标 L3。阶段 1 先做 M05-1/2/5/6 的基础任务，阶段 2 回访索引与事务，阶段 3 验证恢复。

## 最小实验与项目映射

**实验 A：客户成交额。** 生成含“无订单客户、多个订单、多行明细、已取消订单”的数据。分别用错误 JOIN 聚合和正确口径查询，解释重复累计的原因。加入按负责人和时间段筛选，比较联合索引方案。

**实验 B：事务时序。** 两个独立连接显示隔离级别、自动提交状态与每条 SQL 顺序；在 RC/RR 下分别执行普通 SELECT、锁定读、UPDATE。记录返回值和等待，不把别的引擎结论直接搬到 InnoDB。

**实验 C：迁移与恢复。** 用“新增可空字段→兼容写入→回填→校验→加约束”演练客户等级变更。对练习库备份，在全新实例恢复并核对条数、金额合计及抽样明细。

| 场景 | 验证 |
|---|---|
| 正常 | 报价转订单与明细同一事务提交；查询金额与手算一致 |
| 边界 | 无订单客户、金额 0、数据倾斜、深分页、长事务 |
| 失败 | 唯一键冲突、事务中途异常、反序加锁、连接泄漏、迁移中断 |

## 自测与模块验收

1. 有联合索引为什么仍可能全表扫描？通过：从选择性、统计信息与代价解释，并拿执行计划验证。
2. RC 与 RR 中普通查询和 UPDATE 使用同一种可见性规则吗？通过：用明确版本与时序回答，不只背隔离级别表。
3. 已备份为何仍可能达不到恢复目标？通过：解释恢复时间、丢失窗口及验证方法。
4. 参数化查询能解决动态表名/排序字段的注入吗？通过：区分值绑定与标识符白名单。

至少一条聚合 SQL、一组隔离实验、一份索引对比和一次恢复验证；阶段 1 只先验收对应基础单元，不要求提前完成全模块。

## 一手资料与阅读顺序

主入口：[MySQL 8.4 手册](../resources/REFERENCES.md#mysql)：SQL/数据类型 → InnoDB 事务与锁 → 索引与优化 → Backup and Recovery。数据访问查 [MyBatis 官方资料](../resources/REFERENCES.md#mybatis)。所有实验记录精确版本和隔离级别。

## 选修与边界

PostgreSQL 作为另一种实现对照；LSM、列存、NewSQL、存储引擎开发为选修。分库分表先比较索引、归档、读模型等更简单方案，进入 M11 决策后再实践。
